# Enrichment: как улучшать подачу, не трогая содержание

Меняется подача, не содержание. Любая новая надпись — UI-строка в `content/ui-strings.json`, согласованная на шаге 3 («Show table», «Skip to content», «Your team», «Visit Veriff», «Open in new tab»). Всё остальное `compare.mjs` пометит как лишнее.

## Правила

- **Числа в графиках только из источника.** Ширины баров считаются из чисел, но подписи — исходные строки (`36%`, а не пересчитанное `35.6%`).
- **Счётчик заканчивается точной исходной строкой** (`12.5K+`, `97.60%`, `11,898`) и резервирует ширину, чтобы соседи не прыгали. Рантайм делает это сам.
- **Таблица не исчезает**, даже если рядом график: данные доступны скринридеру и для проверки.
- **Ничего не добавлять ради красоты**: никаких поясняющих тултипов («FAR — False Acceptance Rate»), подзаголовков секций, подписей осей, которых нет в источнике, — либо согласовать как UI-строки.
- **Анимации сдержанные**: появление 10–20px + opacity, stagger ≤ 280ms, `prefers-reduced-motion` всё отключает, без JS всё видно.
- **Мобильная версия — отдельное решение для каждого сложного блока** (орбита → сетка; хотспоты → список; таблица → горизонтальный скролл внутри своего блока).
- Пустые области источника (половина слайда без контента) не заполнять выдумкой: предложить варианты на шаге 3 (видео из RELAYTO-версии, фото с сайта, перекомпоновка).

## Хедер над светлым и тёмным hero

Состояние хедера «прозрачный над hero» зависит от яркости hero: над светлой обложкой — тёмный логотип и ссылки, после прокрутки — светлые на тёмном фоне (буклет UAENO). Без JS хедер должен быть в сплошном читаемом состоянии.

## Второй язык

Два случая:
- **Источник сам двуязычный** (буклет UAENO): оба языка — контент источника. Оба лежат в DOM (`lang="en"` / `lang="ar"` на блоках), переключение меняет `lang`/`dir` на `<html>` и CSS показывает нужный. Плюс: `compare.mjs` проверяет оба языка сразу (469 строк в буклете), а UI-строки заводятся парами.
- **Источник одноязычный, сайт двуязычный** (UAENO reskin): переключатель — **только если пользователь согласен**, это новый контент.

Общие правила:
- При переключении держи читателя в той же секции: высоты языков разные, найди текущую секцию до переключения и верни её под хедер после (`scrollIntoView` без анимации).
- `alt` переключается вместе с языком (`data-alt-en` / `data-alt-ar`).
- Перевод — из официальных текстов клиента, где они есть (арабская версия сайта, пресс-релизы); остальное помечается в отчёте как машинный перевод, который должен вычитать носитель языка.
- Для одноязычного источника: словарь «исходная строка → перевод» (`i18n.<lang>.json`) встраивается в HTML при сборке; переключение на месте, без перезагрузки: текстовые узлы, `aria-label`, `alt`, тултипы, `title`, meta description.
- Для RTL-языков: `dir="rtl"` на `<html>`, проверить зеркальность навбара, иконок-стрелок, таймлайна, отступов (логические свойства `margin-inline-start` и т.п.).
- Выбор языка сохраняется в `localStorage` **в try/catch** — во встраивании RELAYTO хранилище может быть недоступно; тогда выбор живёт до конца визита.
- Подпись кнопки («AR» / «EN») и её aria — UI-строки. `compare.mjs` проверяет английскую версию; арабскую — отдельной инвентаризацией после переключения и сверкой со словарём.

## Reskin-режим (инпут html)

Enrichment выключен: те же компоненты, тот же порядок. Допустимо по согласованию — визуал без нового текста: декор сайта (паттерны, разделители, «волны»), обработка фото, стиль анимации, фоновое видео в hero, фото-плитки рядом с текстом (UAENO: мозаика из фото оркестра в Ensemble и во вкладках About, фото в CTA). Каждое такое добавление — в плане на шаге 3 и в таблице изображений в отчёте.
