# Дизайн и ассеты сайта клиента

## Захват

```
node <skill>/scripts/capture_site.mjs https://client.com https://client.com/about https://client.com/gallery \
     --out reference/site --download assets-pool
node <skill>/scripts/contact_sheet.mjs assets-pool --out reference/assets-contact-sheet.png
```
- **WordPress-сайты**: скрипт сам добавляет всю медиатеку через `/wp-json/wp/v2/media` с оригинальными URL и размерами. На UAENO это 53 файла против 17 на главной — среди них фото из статей и галерей, до которых обход не доходит.
- Передавай страницы явно: навигация многих сайтов собрана на JS со ссылками `#`, и автообход (`--crawl`) их не найдёт. Ищи страницы с фото: about, gallery, stories/news (статьи!), leadership, concerts/events, case studies.
- **Защита от ботов** («Checking your browser», «Confirm you are human»): скрипт останавливается и ничего не обходит. Варианты: взять захват из прошлого проекта этого клиента (UAENO PDF-прогон так и сделал — `reference/site` и пул ассетов скопированы из reskin-проекта), попросить пользователя сохранить страницы из своего браузера («Сохранить как → веб-страница полностью» + скриншоты) и работать с файлами, или попросить у клиента брендбук и фото.
- Cookie-баннер: скрипт жмёт «Reject all»/«Decline» (приватный вариант), остатки и чат-виджеты прячет CSS.
- Выход: скриншоты, `styles.json` (computed styles ключевых элементов, частоты цветов/шрифтов/радиусов, CSS-переменные `:root`, загруженные шрифты), `assets.json` (каждый ассет: лучший URL в исходном разрешении, размеры, где стоит, соседний текст, флаг `suspect`), `logos/*.svg` (инлайн-SVG из шапки/футера).

## Токены (`styles/tokens.css`)

- CSS-переменные: палитра, шрифты, шкала размеров, межстрочные, трекинг, uppercase-заголовки, радиусы, тени, отступы, брейкпоинты.
- **У каждого токена — комментарий с источником**: `site` (computed styles), `PDF` (цвет заливки из PDF), `site + PDF` (совпадает). Как в Veriff: `--teal-800: #0c3035; /* brand dark: text, dark sections   site + PDF */`.
- Цвета берутся с сайта, а не «на глаз» со скриншота; если у PDF/исходника есть фирменные цвета — сверить.

## Шрифты

- Тот же шрифт, что на сайте. Открытые лицензии (Inter, Montserrat, Noto — SIL OFL 1.1) — self-host, `OFL.txt` рядом.
- Коммерческие шрифты сайта (Helvetica LT Pro, Editor Condensed…) — **только по явному решению пользователя** на шаге 3 (UAENO: «закрытое демо для клиента», использованы файлы шрифтов с сайта клиента). Иначе — ближайший открытый аналог. Решение и лицензионная оговорка — в отчёт.
- Подмножества `latin` + `latin-ext` в woff2 с `unicode-range`, `font-display: swap`. При упаковке шрифты встраиваются в HTML как data: (CDN-шрифты без CORS-заголовка браузер заблокирует).

## Компоненты

Составь таблицу «компонент источника → компонент в стиле клиента»: кнопки (primary/secondary), карточки, бейджи/eyebrow, таблицы, цитаты, хедер, футер, разделители, декоративные паттерны (орнамент UAENO, dark-bg-pattern Veriff), обработка фото (оверлеи, маски, рамки). Не копируй CSS сайта целиком — переноси решения в свои токены и компоненты.

## Ассеты: правила отбора

1. **Обязательно с сайта клиента**, когда пользователь так сказал (UAENO), иначе — из источника + сайт как дополнение (Veriff: платформенный скриншот, телефоны с UX-флоу, постеры видео с veriff.com).
2. **Исходное разрешение.** `capture_site.mjs` убирает параметры ресайза (`i0.wp.com/…?fit=300,300` → оригинал в `/wp-content/uploads/`, суффиксы `-300x200`, `?width=&rmode=`) и берёт максимум из `srcset`. Hero ≥ 1920px по ширине; фото в колонке ≥ 1200px.
3. **Плейсхолдеры не использовать.** Флаг `suspect` в `assets.json`: имя файла (`placeholder`, `Mask-group-*`, `elementor/assets/images`), соседний текст-рыба («MUSICIAN NAME», «Description Description», «This is a paragraph area»), один файл под разными подписями много раз, крошечный размер, трекинговые пиксели. На сайте UAENO так помечены 9 из 17 ассетов главной.
4. **Классифицируй каждый файл пула** в `assets-pool/manifest.json`: что изображено (одной фразой), тип (photo / portrait / artwork with text / partner artwork / poster / logo / pattern / icon) и решение («да: hero», «запасной для tour», «нет: artwork with text», «нет: partner artwork»). Афиши и баннеры с надписями, партнёрские артворки, постеры концертов в слоты не идут — только «чистые» фото. Так сделано в UAENO, и это сильно упрощает выбор на шаге 3.
5. **Подбор под слоты.** Для каждого слота: смысл слота (что должно быть изображено), основной вариант + 1–2 запасных, превью (`contact_sheet`). Одно фото не использовать дважды. Фото по смыслу: дебют в музее — фото из статьи про дебют; тур/обучение — репетиция или мастер-класс; hero — самое сильное сценическое фото.
6. **Логотипы**: SVG с сайта (светлая и тёмная версии под фон). Логотипы партнёров/кейсов — из источника; логотип без альфа-канала с «запечённым» фоном работает только на том же цвете фона.
7. **alt переписывается под новое изображение** — точное описание того, что на фото. Таблица «слот → было → стало → alt» идёт в итоговый отчёт.
8. Видео не скачивай автоматически (они большие): выбери осознанно, сделай 2 размера (1920 и 960), постеры для каждого.

## Подготовка файлов

- Понятные уникальные имена по смыслу слота: `hero-orchestra-1600.webp`, `debut-zayed-national-museum-720.webp`, `tour-rehearsal-violinists-800.webp`.
- Адаптивный набор для `srcset` + `sizes`: hero 480 / 800 / 1200 / 1600 / 2000, фото в колонке 480 / 720(800) / 1200 / 1600 — по реальной ширине отображения ×2. Мелкие декоративные фото (плитки) — один размер.
- Формат — **webp** для режима RELAYTO Files (проверено на UAENO, отдаётся как `image/webp`); avif с сайта конвертируй в webp. Для режима хаба — jpg/png (так было в Westinghouse; webp в хабе не проверялся — проверь первый файл `check_map.mjs`).
- Видео hero: mp4 H.264, без звука, 1920 и 960 (или один ~1280, если короткий), постер — первый кадр или фото того же сюжета.
- Сохраняй `_built.json`: файл → из какого исходника, размер, вес — это «таблица замен» для итогового отчёта.
