# Инпут: PDF (презентация, отчёт, буклет)

Эталоны: **Veriff × SIXT** (18 слайдов 16:9, экспорт Chrome/Skia, шрифты Type3) и **To This Land, We Belong** (концертный буклет UAENO, 28 страниц, InDesign, двуязычный EN/AR, читается с двух концов).

## Шаги

1. Положи PDF в `source/`. Запусти:
   ```
   python <skill>/scripts/pdf_extract.py source/deck.pdf --out reference
   ```
   Получишь рендеры `reference/pdf-pages/page-NN.png` (2x), строки с размером/жирностью/цветом/координатами `pdf-lines.json`, картинки `pdf-images/`, ссылки и отчёт `pdf-report.md`.
2. **Рендер — главный эталон.** Если извлечённый текст расходится с картинкой, прав рендер. Открывай рендер каждой страницы, когда собираешь её содержимое.
3. Собери `content/content.json` (схема ниже) **вручную/полуавтоматически по страницам**, сверяясь с рендером. Иерархию заголовков определяй по размеру и жирности из `pdf-lines.json`, а не по смыслу.
4. Таблицы — поячеечно, каждая ячейка сверена с рендером. В Veriff таблиц оказалось 7, а не 4 «очевидных»: перцентили, три таблицы на одной странице, воронка, два списка причин с барами.
5. Картинки из PDF: логотипы клиента и партнёров, фото команды, иконки. Векторные логотипы и иконки вытаскивай как SVG (контуры со страницы), если они нужны в вебе — так было с логотипом Veriff и 7 иконками.
6. Если у PDF есть **RELAYTO-версия** (пользователь её упомянет или даст ссылку): открой её Playwright'ом, собери интерактивный слой — видео (YouTube/mp4) и их хотспоты, ссылки на LinkedIn, переходы. Это **не текст PDF**: храни в `content.json → relayto` отдельно, в видимый текст по умолчанию не попадает; что из этого показывать — решается на шаге 3. В Veriff так нашлись видео для пустой панели на стр. 3 и пустой половины стр. 18 и ссылки на профили команды.
7. Валидация: каждая страница — набор символов и все числа в `content.json` совпадают с PDF (без учёта пробелов). Это ловит потерянные и выдуманные строки ещё до вёрстки.
8. `content/report.md` — по образцу ниже.

## Типичные артефакты извлечения (чинить, сверяясь с рендером)

| Артефакт | Пример (Veriff) | Как чинить |
|---|---|---|
| Склеенные слова в крупных заголовках (плотный трекинг) | `Verifiedin seconds.Onthe` | `pdf_extract.py` уже ставит пробелы по геометрии глифов; остатки — по рендеру |
| Крупная цифра порвана и перемешана с подписью | `9 APPROVA 7 L RAT . E, F 6…` → `97.60%` + `APPROVAL RATE, FINAL DECISIONS` | строки по геометрии уже целые; проверь все крупные цифры по рендеру |
| Нет пробела после точки/запятой | `SIXT.We want`, `specialists,VPs` | восстановить пробел, формулировку не трогать |
| Колонки слиплись в одну строку | `97% 50 90%`, имена команды подряд | разнести по своим блокам |
| Строки соседних карточек перемешаны | текст 2-й и 3-й карточек вперемешку | разнести по карточкам по координатам |
| Диаграмма стала плоским списком | орбита «SIXT + 8 ролей» | сохранить структуру: центр, узлы, углы, порядок по часовой |
| Апострофы/пробелы | прямой `'` в одном месте; узкий пробел в `4.3 s` | привести к тому, что видно на рендере, единообразно |

`pdf-report.md` подсвечивает подозрительные строки (CamelCase-склейки, обрывки крупного текста). Там бывают ложные срабатывания на названиях брендов (`BlaBlaCar`, `CrossLinks`) и идентификаторах (`resubmission_requested`) — это нормально, просто подтверди.

## Особые случаи PDF (из буклета UAENO)

- **Страницы без текстового слоя** (обложка с обведёнными в кривые надписями): слова переписываются с рендера. `pdf-report.md` перечисляет такие страницы.
- **Текст внутри картинок** (коллажи с именами и названиями): это не текст страницы — он идёт в `alt` картинки. Картинку с «запечённым» текстом нельзя чистить или переверстать — только показывать целиком.
- **Перенос в конце строки**: решай по рендеру и смыслу — мягкий перенос склеивается (`perfor-` / `mance`), составное слово сохраняет дефис (`best-` / `known` → `best-known`).
- **Курсив** в названиях произведений и т.п. сохраняется как выделение (`em` в content.json).
- **Многослойная обложка**: картинки страницы часто лежат слоями (фон, инструменты, флаг, надписи-кривые отдельно). Из слоёв можно пересобрать широкий hero с лёгким параллаксом, оставаясь в оригинальном визуале.
- **Фото низкого разрешения** в PDF (968 px при полноширинном слоте) — замени фото того же сюжета с сайта клиента и запиши замену в таблицу изображений.
- Пустые/служебные страницы и повторённая вторая обложка в контент не идут; колонтитулы — тоже.

## Двуязычные PDF и письмо справа налево

- Буклет, который **читается с двух концов** (EN с начала, AR с конца, вторая половина — зеркало первой): строй **одно** дерево контента, где у каждого блока есть оба языка (`text` и `ar`), а не два документа. Отметь в отчёте, какая страница какой зеркальна, и расхождения переводов между языками (в UAENO: «второй сезон» в арабском против «Season 26/27» в английском) — это тоже «данные как есть».
- **Текстовый слой арабского (и других RTL) почти всегда ненадёжен**: в одних шрифтах буквы на месте, но пары лигатур переставлены (`حنني` вместо `حنين`), шадда дублирует букву (`عررّبر` = `عبّر`); в декоративных шрифтах — мусор. Порядок слов читай с рендера при большом увеличении (кропы в `reference/ar-crops/`).
- **Побуквенная проверка**: `python <skill>/scripts/pdf_letters.py source/x.pdf content/ar-pages.json --skip-fonts Manchette --exclude "\|"` — на каждой странице набор букв транскрипции должен покрывать набор букв текстового слоя (порядок не важен). Строки декоративных шрифтов исключаются и сверяются глазами. Ключи `ar-pages.json` — номера страниц, где текст реально стоит.
- Кашида (U+0640) — растяжка для выключки, не текст.
- **Обязательная пометка в отчёте**: арабский текст (и любые арабские UI-строки и alt, написанные для страницы) должен вычитать носитель языка до показа клиенту — особенно имена и титулы.
- Шрифты: если фирменные арабские шрифты буклета недоступны, подбери открытый аналог (UAENO: Noto Kufi Arabic, OFL); арабский заголовок можно взять кривыми из PDF как SVG, чтобы сохранить оригинальное начертание.

## Данные оставляются как есть

Буклет UAENO: разное написание одного названия на разных страницах (`LIGHTNING, THUNDER & LONGING` и с лишней запятой в коллаже), `Season 26/27` и `SEASON 26 / 27`, смешанный регистр заголовков ростера, имена как напечатаны (`Guttierez`, `HawYuan Cheng`). Veriff:

- Две метрики с похожими названиями: 97.60% (от финальных решений) и 87% (от всех проверенных сессий).
- Итог таблицы 9,165 при общем числе 11,898 — сноска объясняет, что это только сессии с известной страной.
- Шаг 09 воронки (8,837) больше шага 08 (8,832).
- 97.6% рядом с 97.60%, 3.7% рядом с 3.74% — округления на разных слайдах.
- «United States» и «United States of America» на разных слайдах.
- Статусы-идентификаторы (`resubmission_requested`) — строчными, как в источнике.

## Схема content.json

```json
{
  "meta": { "source": "source/deck.pdf", "pages": 18, "pageSizePt": [720, 405],
            "note": "Single source of text. 1:1 with the PDF; only extraction artefacts repaired (see report)." },
  "sections": [
    { "id": "test-results", "number": "03", "title": "Test results", "pages": [8, 15],
      "subsections": [
        { "id": "summary-and-accuracy", "title": "Summary and accuracy", "pages": [8, 9],
          "blocks": [
            { "type": "heading", "level": 2, "text": "Accurate decisions.", "page": 8 },
            { "type": "stat", "value": "97.60%", "label": "APPROVAL RATE, FINAL DECISIONS", "page": 8 },
            { "type": "paragraph", "text": "…", "page": 8 },
            { "type": "table", "caption": "Response time percentiles", "columns": ["", ""], "rows": [["P80", "6.8 s"]], "page": 9 },
            { "type": "bars", "rows": [{ "label": "United States", "value": "36%" }], "page": 10 },
            { "type": "image", "src": "assets/img/hero-phone.jpg", "alt": "…", "page": 1 }
          ] } ] }
  ],
  "relayto": { "note": "Interactive layer of the RELAYTO version — NOT PDF text.", "items": { } }
}
```
Ключи с видимым текстом (`text`, `title`, `label`, `value`, `caption`, `name`, `role`, `detail`, `qualifier`, …) проверяет `compare.mjs`; `alt`, `src`, `id`, `type`, `page`, `note`, `relayto` — не считаются текстом PDF. Подписи навбара берутся из слайда Agenda, если он есть.

## Отчёт фазы 1 (content/report.md)

1. Источник: страниц, формат, как экспортирован, где эталон.
2. Таблица «страница → раздел → что на странице».
3. Исправленные артефакты: было → стало (все, включая пробелы).
4. Данные, оставленные как есть.
5. Таблицы (сколько, где, сверены ли поячеечно).
6. Изображения: файл, исходник, размер, ограничения (например, логотип без альфы с «запечённым» фоном годится только на том же цвете).
7. Сомнительное / требует решения: пустые области слайдов, кнопки play без ссылки, ссылки из RELAYTO-версии, метаданные PDF (title не идёт в контент).
